# Справочник: средства C++ в этом проекте

Краткие карточки «что это / зачем здесь / где смотреть / на что обратить внимание». Полезно читать с открытым кодом: каждая карточка соответствует конкретному месту в `src/`.

## 1. Владение ресурсами

### `std::unique_ptr<T>` — исключительное владение

```cpp
using SourcePtr = std::unique_ptr<IVideoSource>;
```

* **Зачем**: `V4l2Source` владеет файловым дескриптором и mmap-областями. Двух владельцев быть не может — копирование недопустимо.
* **Где**: `pipeline.hpp` (`SourcePtr`, `SegmenterPtr`), pimpl в `v4l2_source.cpp`/`onnx_segmenter.cpp`.
* **Подводные камни**: `unique_ptr<Base>` с виртуальным деструктором в `Base` — иначе `delete` через базовый указатель не вызовет `~Derived`. У `IVideoSource` деструктор виртуальный.
* **Почему не «сырой» указатель + `delete`**: ручное освобождение пропускается при раннем `return` или исключении.

### `std::shared_ptr<const T>` — разделяемое неизменяемое владение

```cpp
using FramePtr  = std::shared_ptr<const Frame>;
using ResultPtr = std::shared_ptr<const InferenceResult>;
```

* **Зачем**: один кадр нужен очереди, результату инференса и UI одновременно.
* **`const` в типе** — не украшение: он делает попытку записи в разделяемые данные **ошибкой компиляции**, а не гонкой данных в рантайме.
* **Цена**: атомарный инкремент счётчика ссылок на копирование (десятки наносекунд) — для 30–60 кадров в секунду незаметно.
* **`std::make_shared<T>(...)`** — одно выделение вместо двух (объект + контрольный блок), лучше локальность кеша.
* **`std::static_pointer_cast<const T>` / преобразование `shared_ptr<T>` → `shared_ptr<const T>`** — неявное, безопасное (добавление `const`), обратное требует `const_pointer_cast` (и здесь не используется).

### RAII и правило нуля/пяти

Классы с владельческими ресурсами:

| Класс | Что владеет | Освобождение |
|---|---|---|
| `V4l2Source` | fd, mmap-буферы | `~V4l2Source()` → `STREAMOFF` → `munmap` → `close` |
| `OnnxSegmenter` | `Ort::Session`, `Ort::Env` | деструкторы `Ort::*` |
| `Pipeline` | два `std::thread` | `stop()` + `join()` из деструктора |
| `cv::VideoWriter` | файл/кодек | `release()` или деструктор |

Правило: **каждый ресурс — в своём RAII-объекте**, тогда исключение в середине функции не приведёт к утечке.

## 2. Многопоточность

### `std::mutex` + `std::condition_variable`

```cpp
std::unique_lock lock(mutex_);
not_empty_.wait(lock, [this] { return closed_ || !items_.empty(); });
```

Три обязательных детали:

1. **Предикат обязателен.** `wait` без предиката может проснуться «сам по себе» (spurious wakeup) — это разрешено стандартом. Предикат — единственная защита.
2. **`std::unique_lock`, а не `lock_guard`**: `wait` отпускает и снова захватывает мьютекс; `lock_guard` этого не умеет.
3. **`notify_one()` при добавлении, `notify_all()` при закрытии.** Первое будит одного потребителя (достаточно для одного элемента), второе — всех, кто ждёт и не дождётся.

### `std::atomic<T>` и модель памяти

```cpp
std::atomic<std::uint64_t> frames_captured{0};
frames_captured.fetch_add(1, std::memory_order_relaxed);
```

* **`memory_order_relaxed`** — атомарность есть, упорядочивания с другими переменными нет. Правильно для счётчиков статистики: каждое число имеет смысл само по себе, их согласованность между собой не требуется.
* **`memory_order_acquire/release`** нужны, когда атомик «публикует» данные. В этом проекте публикация кадров идёт через мьютекс очереди, поэтому более сильные порядки не требуются. (Это не случайность, а следствие дизайна: атомики — только для метрик и флага.)
* **`std::atomic<bool>` в обработчике сигнала** — единственное, что разрешено делать в нём кроме `_exit`. `static_assert(std::atomic<bool>::is_always_lock_free)` гарантирует отсутствие внутреннего мьютекса.

### `std::thread` и корректное завершение

```cpp
Pipeline::~Pipeline() { stop(); }  // закрыть очереди, дождаться join
```

* Поток, который не `join`-нут и не `detach`-нут, при разрушении `std::thread` вызывает `std::terminate()`.
* `detach()` не годится: поток может обратиться к уже разрушенному объекту (`this`).
* Поэтому: флаг остановки → `close()` очередей (разбудить всех) → `join()`.
* Исключение внутри потока → `std::terminate()`: все потоки ловят свои исключения.

### Идемпотентная остановка

```cpp
void Pipeline::stop() {
    if (!running_.exchange(false)) return;   // уже остановлен
    ...
}
```

`exchange` возвращает предыдущее значение и атомарно записывает новое — классический приём «действие ровно один раз» без мьютекса.

## 3. Шаблоны

### Класс-шаблон: `BoundedQueue<T>`

```cpp
template <class T>
class BoundedQueue { /* ... */ };
```

* Инстанцируется для `FramePtr` и `ResultPtr`; специализация нужна **на этапе компиляции** — виртуальные вызовы не окупаются на горячем пути.
* Шаблонный код обычно живёт в заголовке: компилятору нужно видеть тело, чтобы инстанцировать.

### Шаблонная функция с `if constexpr`-подобной задачей: `xioctl`

```cpp
template <class... Args>
int xioctl(int fd, unsigned long request, Args&&... args) {
    int result;
    do { result = ::ioctl(fd, request, std::forward<Args>(args)...); }
    while (result == -1 && errno == EINTR);
    return result;
}
```

* **Variadic template + perfect forwarding** (`Args&&`, `std::forward`) — обёртка работает с любым числом аргументов `ioctl` (у разных запросов их 0–1, но сигнатура разная).
* `do/while` вокруг вызова — повтор при `EINTR`: системный вызов может быть прерван сигналом, и это не ошибка.

### Шаблонный параметр-время: `pop_wait_for`

```cpp
template <class Rep, class Period>
std::optional<T> pop_wait_for(std::chrono::duration<Rep, Period> timeout);
```

Так метод принимает `100ms`, `std::chrono::milliseconds(10)` и даже `1.5s` без перегрузок и без приведения к одной единице вручную. Внутри — `condition_variable::wait_for`, который сам конвертирует в свои часы.

## 4. `std::optional` вместо «магических» значений

```cpp
std::optional<T> try_pop();     // nullopt = «пусто», а не T{} и не -1
```

* Явное «значения нет» без дополнительного bool-выходного параметра и без исключений на нормальном пути.
* `if (auto v = queue.try_pop())` — `operator bool` проверяет наличие, `*v` даёт значение.
* В `LatestValue::get()` возвращается `std::optional<T>` — копия `shared_ptr` (или `nullopt`).

## 5. `std::chrono`

```cpp
using SteadyClock = std::chrono::steady_clock;
duration<double, std::milli>(b - a).count();     // миллисекунды как double
std::this_thread::sleep_until(deadline);
```

* **`steady_clock`** — монотонные часы: не «прыгают» при смене системного времени. Обязательны для измерения интервалов и таймаутов.
* **`system_clock`** — только для отображения времени суток (в логгере).
* **`duration<double, std::milli>`** — время как число с плавающей точкой в миллисекундах; удобно и без потери точности на коротких интервалах.
* **`sleep_until(deadline)`** вместо `sleep_for(interval)` в темповом ограничителе: накапливающийся дрейф `sleep_for` (каждый вызов добавляет задержку планировщика) здесь недопустим.

## 6. Перечисления и `enum class`

```cpp
enum class NextStatus { Frame, Timeout, Error, EndOfStream };
```

* **`enum class`** вместо `enum`: не преобразуется неявно в `int`, имена не «протекают» в объемлющую область (`NextStatus::Error`, а не `Error`, которое может конфликтовать).
* Исчерпывающий `switch` по `enum class` — компилятор с `-Wswitch` предупредит о забытом значении (в `capture_loop` обработаны все четыре).
* `enum class OverflowPolicy` в шаблоне очереди — пример того, как перечисление параметризует поведение без наследования и виртуальных вызовов.

## 7. Функции высшего порядка и лямбды

```cpp
capture_thread_ = std::thread([this] { capture_loop(); });
```

* Поток запускается лямбдой, захватывающей `this`. Время жизни объекта должно превышать время жизни потока — это обеспечивается `join()` в деструкторе.
* Лямбда-предикат в `wait(lock, [this]{...})` — пример замыкания, которое вызывается под мьютексом.
* `std::thread` не копируемый, только перемещаемый — поэтому `capture_thread_` член инициализируется присваиванием временного объекта (move).

## 8. Компиляторные гарантии и контракты

| Средство | Пример | Что даёт |
|---|---|---|
| `override` | `bool open(std::string&) override;` | ошибка компиляции, если сигнатура не совпала с виртуальной |
| `final` | `class V4l2Source final` | запрет наследования, возможная девиртуализация |
| `= delete` | `BoundedQueue(const BoundedQueue&) = delete;` | запрет копирования на уровне языка |
| `= default` | `~OnnxSegmenter() override = default;` | явное намерение, полное определение в .cpp при pimpl |
| `noexcept` | `std::size_t capacity() const noexcept` | контракт «не бросает»; важно для деструкторов и move-операций |
| `const`-методы | `dropped() const` | читатели не меняют состояние, можно вызывать на `const`-объекте |
| `explicit` | `explicit V4l2Source(V4l2Config)` | запрет неявных преобразований в конструкторе с одним аргументом |
| `static_assert` | `is_always_lock_free` | проверка инварианта на этапе компиляции |
| `[[nodiscard]]` | (там, где результат нельзя игнорировать) | предупреждение за забытый результат |
| `constexpr` | `constexpr std::array<cv::Scalar, 20> kPalette` | вычисление на этапе компиляции |

## 9. Строки и форматирование

* **`std::string_view`** — «вид» на строку без владения и без копирования: `parse_log_level(std::string_view, LogLevel&)`, `to_string(LogLevel)`.
* **`std::ostringstream`** в `LogMessage` — конструкция «лог накапливается в объект, пишется в деструкторе». Так строки не перемешиваются между потоками, и нет нужды в `std::format` (которого нет в libstdc++ до GCC 13).
* **`std::snprintf`** для HUD и логов с числами — предсказуемо и быстро; важно передавать размер буфера (`sizeof(buffer)`), а не надеяться на «хватит».
* **`std::to_string`** для простых случаев: `std::to_string(info_.class_count)`.

## 10. Исключения vs коды возврата

Правило проекта: **исключения не пересекают границу модуля и не вылетают из потоков**.

```cpp
try {
    ...
} catch (const Ort::Exception& e) {
    error = std::string("ONNX Runtime: ") + e.what();
    return false;
}
```

* Внутри библиотек (ORT, OpenCV) исключения — нормальный механизм.
* На границе `ISegmenter::segment` они превращаются в `bool` + `std::string error`: это делает API вызываемого кода однородным и предсказуемым.
* В потоках — обязательно: непойманное исключение в `std::thread` вызывает `std::terminate()` без возможности что-либо сделать.

## 11. `cv::Mat`: что нужно знать

`cv::Mat` — дескриптор, а не «массив». Полезно помнить:

* **Копирование `cv::Mat`** — поверхностное (счётчик ссылок на буфер). `clone()` — глубокая копия.
* **`cv::Mat` из чужой памяти** — `cv::Mat(rows, cols, type, ptr, step)`; владения нет, `ptr` должен жить, пока живёт матрица (используется для mmap-буфера камеры и массива `std::vector<float>`).
* **`step`** — длина строки в **байтах**, может быть больше `cols * elemSize` (выравнивание). Игнорирование `step` — источник «съехавшей» картинки.
* **`findContours` портит вход** — нужен `clone()`.
* **`convertTo(roi, -1, alpha, beta)`** работает **на ROI in-place** (ROI — это «вид» на оригинал), поэтому `canvas(panel).convertTo(...)` меняет оригинал. Это используется в `draw_hud` для затемнения подложки.
* **Типы**: `CV_8UC3` (BGR-кадр), `CV_8UC1` (маска), `CV_32F` (вход модели, промежуточные маски).
* **`setTo(color, mask)`** — заливка по маске без циклов: одна векторная операция.
* **`addWeighted(a, α, b, β, γ)`** — `α·a + β·b + γ` с насыщением; здесь применяется для полупрозрачного слоя масок.

## 12. Паттерны проектирования, задействованные в коде

| Паттерн | Где | Смысл |
|---|---|---|
| **Strategy (полиморфизм)** | `IVideoSource`, `ISegmenter` | подмена камеры/файла/модели без изменения конвейера |
| **Factory** | `make_source()`, `make_segmenter()` в `main.cpp` | выбор реализации по конфигу в одном месте |
| **Pipeline / Producer-Consumer** | `Pipeline` + `BoundedQueue` | стадии работают параллельно, буферы ограничены |
| **Pimpl** | `V4l2Source::Impl`, `OnnxSegmenter::Impl` | скрыть зависимости и детали реализации |
| **RAII** | все владельческие классы | освобождение ресурсов в деструкторе |
| **Null Object** | `NullSegmenter` | «модели нет» — валидное состояние, а не `if (model)` в каждом вызове |
| **Observer-подобный опрос** | `PipelineStats` | UI читает метрики, не блокируя обработку |
| **Snapshot / immutable value** | `Frame`, `InferenceResult` | потокобезопасность через неизменяемость |

## 13. Частые ошибки в подобных проектах и как здесь закрыты

| Ошибка | Симптом | Решение в коде |
|---|---|---|
| Забыт `VIDIOC_QBUF` после `DQBUF` | картинка «замерзает» через N кадров | `QBUF` вызывается всегда, даже при ошибке конвертации |
| Не учитывается `bytesperline` | изображение «едет» по диагонали | `step` передаётся в `cv::Mat` явно |
| `DQBUF` без `poll` / busy-loop | 100% CPU на одном ядре | `poll` с таймаутом |
| `close()` без `munmap` | утечка адресного пространства | `munmap` до `close` в `close_device` |
| Неверный порядок каналов | точность ниже ожидаемой, без ошибок | `swapRB=true` в `blobFromImage` |
| Нет letterbox | координаты масок смещены по осям | `LetterboxTransform` — одна точка правды |
| `findContours` на маске из другого потока | случайные пиксели, «дыры» в маске | маска клонируется перед `findContours` |
| Накопление альфы | перекрытия темнеют | один слой + один `addWeighted` |
| `system_clock` для латентности | отрицательные значения | `steady_clock` |
| `wait` без предиката | «зависания» и ложные пробуждения | везде предикат |
| `join()` без `close()` очередей | вечное зависание при выходе | `close()` → `notify_all` → `join` |
| Исключение в потоке | `std::terminate()` | `try/catch` на границе потока |
| Копирование кадра на каждую стадию | лишние 2.7 МБ × N копий на кадр | `shared_ptr<const Frame>` |
| Неограниченная очередь | рост памяти и задержки | `BoundedQueue` с `DropOldest` |
